# M4 需求文档：Dashboard 可视化 + Agent 联动

## 1. 背景与目标

M1-M2 已完成权限网关后端（cockpit-api）：JWT 认证、RBAC 策略、字段级脱敏、审计日志。所有 API 已就绪并通过验收（63 个 RSpec 测试全部通过）。

M4 的目标是将权限网关与 AI Agent（OpenClacky）打通，让用户通过自然语言查询业务数据，同时严格遵守权限边界。

**核心定位**：Agent 对话是主界面，Dashboard 报表是后续扩展。

## 2. 用户角色与场景

### 2.1 第一优先级：数据分析师

分析师通过 AI Agent 用自然语言查询业务数据，权限网关在每次查询时自动校验并脱敏。

**使用路径**：

1. 打开浏览器，访问登录页，输入用户名密码
2. 系统验证身份后，进入 OpenClacky Agent 对话界面
3. 在对话框输入："查询华东区本月出租率"
4. Agent 识别查询意图，调用 cockpit-api 权限网关
5. 权限网关校验用户策略，返回授权范围内数据
6. Agent 将结果以表格或列表形式呈现
7. 分析师追问："华北区呢？" → Agent 再次走权限链路返回
8. 全程审计日志自动记录

**关键体验要求**：
- 登录后直接进入 Agent 对话，无需额外操作
- 查询响应速度 ≤ 5 秒（含权限校验 + 数据获取 + Agent 生成）
- 权限不足时给出明确提示（如"您当前角色仅可查看汇总数据"）
- 对话上下文保持，支持连续追问

### 2.2 第二优先级：领导看报表

领导通过 Dashboard 查看关键 KPI 指标卡片，点击指标可触发 Agent 追问。

**使用路径**：

1. 登录后进入 OpenClacky，侧边栏出现"报表"入口
2. 切换到 Dashboard 面板，看到指标卡片（出租率、合同额、客户数等）
3. 数据已按用户权限过滤（如某领导只能看华东区数据）
4. 点击某个指标卡片 → 自动跳回对话界面，预填追问问题
5. Agent 基于点击上下文进行权限网关查询，返回详细分析

**关键体验要求**：
- Dashboard 指标按用户权限动态展示
- 点击追问时自动带入上下文（指标名称、时间范围、区域）
- 图表清晰直观，支持趋势线和对比

## 3. 验收标准

### A1: 统一登录体验

- [ ] 用户访问系统时先看到登录页（用户名 + 密码）
- [ ] 登录成功后自动跳转至 OpenClacky 对话界面
- [ ] JWT 在整个会话期间有效，无需重复登录
- [ ] 未登录时访问 OpenClacky 自动重定向到登录页
- [ ] 登录失败时显示明确的错误提示

### A2: Agent 权限感知查询

- [ ] 分析师在 Agent 对话中输入自然语言查询（如"查询华东区出租率"）
- [ ] Agent 自动调用 cockpit-api 权限网关进行身份和策略校验
- [ ] 拥有完整权限的用户看到全部字段数据
- [ ] 权限受限的用户看到脱敏数据（敏感字段显示 `[FILTERED]`）
- [ ] 无权限的用户收到明确的拒绝说明
- [ ] 每次查询自动写入审计日志（用户、工具、决策、耗时）

### A3: 连续追问与上下文保持

- [ ] 分析师可在同一对话中连续追问
- [ ] Agent 理解追问上下文（"华北区呢"理解为查询华北区出租率）
- [ ] 每次追问均独立走权限校验（不继承上一次授权）
- [ ] 对话历史在当前会话内保持

### A4: Dashboard 报表面板（后续阶段）

- [ ] OpenClacky 侧边栏新增"报表"导航项
- [ ] Dashboard 面板展示 KPI 指标卡片（出租率、合同额、客户数）
- [ ] 数据按当前用户权限过滤展示
- [ ] 点击指标卡片自动跳转对话界面并预填追问问题
- [ ] 支持至少一种图表类型（趋势折线图）

### A5: 审计与安全

- [ ] 所有 Agent 触发的查询均记录审计日志
- [ ] 审计日志包含：用户 ID、查询内容、工具 ID、授权决策、返回字段、耗时
- [ ] JWT token 在传输中加密，不在 URL 参数中暴露
- [ ] Agent 工具调用链路中 token 不经过 LLM 对话内容

## 4. 范围约束

### 本阶段包含

- 统一登录页（cockpit-api 托管）
- Auth Proxy 中间件（JWT 验证 + 用户身份注入）
- cockpit_gateway 自定义 Tool（OpenClacky 原生 Ruby Tool）
- Agent 对话中的权限感知数据查询
- 连续追问与上下文保持
- 审计日志完整记录

### 后续阶段包含

- Dashboard 报表面板（指标卡片 + ECharts 图表）
- 点击指标触发 Agent 追问
- 定时报表推送（Cron）
- IM 集成（飞书/企微消息驱动查询）

### 明确不包含

- 用户注册流程
- OAuth / SSO（Keycloak/MaxKey）
- Dify 工作流集成
- 真实业务系统 API 对接（继续使用模拟数据）
- 多业务系统联动
- 移动端适配
- 用户管理 UI（Admin CRUD 已在 M1-M2 完成，API 可用）

## 5. 技术选型

| 层 | 技术 | 说明 |
|---|---|---|
| 主界面 | OpenClacky Web UI | Agent 对话 + 后续 Dashboard 面板 |
| 认证 | cockpit-api JWT + Auth Proxy | 不在 OpenClacky 内建用户体系 |
| Agent-后端通信 | 自定义 Ruby Tool (cockpit_gateway) | 一等公民 Tool，非 Skill/curl |
| Dashboard 图表（后续） | ECharts CDN | 轻量引入，无构建工具 |
| 后端 | cockpit-api (Rails 8.1) | 已有完整权限网关 |
| OpenClacky 管理 | Git submodule + 补丁注入 | 保持原版可升级 |

## 6. 成功指标

| 指标 | 目标 |
|---|---|
| 端到端查询响应时间 | ≤ 5 秒（权限校验 + 数据获取 + Agent 生成） |
| 权限校验准确率 | 100%（每次查询均走网关，无绕过路径） |
| 审计日志完整性 | 每次查询有记录，包含完整决策链 |
| 分析师操作步骤 | 登录 → 提问 → 获得结果，≤ 3 步 |
